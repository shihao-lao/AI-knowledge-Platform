# 对话消息的归属与角色

添加消息接口要求登录，服务层通过「对话 → 知识库 → 当前用户」检查归属。
请求中的用户 ID 不参与授权，身份只取自登录凭据。

| 角色        | 来源                         | 客户端可提交 |
| ----------- | ---------------------------- | ------------ |
| `user`      | 当前用户的问题               | 是           |
| `assistant` | 后端欢迎语和模型生成的回复   | 否           |
| `system`    | 后端构造的系统 Prompt        | 否           |
| `tool`      | 保留的内部角色，当前聊天未用 | 否           |

`POST /api/v1/conversations/{conversation_id}/messages` 保留查询参数
`role=user` 和 `content`。写入其他用户的对话或不存在的对话均返回 404；
提交 `assistant`、`system`、`tool` 返回 403，未知角色返回 422。
引用信息由后端生成，客户端传入的旧 `citations` 参数不会写入消息。

创建对话时，后端在同一事务中保存一条 `assistant` 欢迎语，返回的
`message_count` 为 1。前端通过消息列表读取欢迎语，不再自行创建助手消息。

聊天历史只将 `user` 和 `assistant` 消息提供给模型。历史中已有的 `system`
消息不会作为系统指令使用；系统指令来自当前服务端 Prompt 模板。
