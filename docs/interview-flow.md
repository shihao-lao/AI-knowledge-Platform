# 模拟面试流程与恢复

在 AI 对话页选择「模拟面试」，按当前知识库、分类和难度选题。
每个对话对应一场面试，完成后新建对话开始下一场。

后端保存选题顺序、题目和参考答案快照、当前题位置、作答及评分：
`answering → reviewing → 下一题 answering / 最后一题 completed`。
恢复对话时直接读取数据库进度，不依赖模型记住聊天历史。
评分复用练习评分服务，每题写入 `PracticeRecord(mode=mock)`，总结保存平均分和复习要点。

| 接口                                         | 用途             |
| -------------------------------------------- | ---------------- |
| `GET /conversations/{id}/interview`          | 读取或恢复进度   |
| `POST /conversations/{id}/interview`         | 选题并开始面试   |
| `POST /conversations/{id}/interview/answers` | 提交当前题并评分 |
| `POST /conversations/{id}/interview/next`    | 下一题或完成总结 |

所有接口都通过「对话 → 知识库 → 当前用户」校验归属。
尚未评分的参考答案不返回客户端；评分后返回参考摘要。
普通聊天接口不接受 `mode=interview`，防止绕过面试状态和统计落库。

评分先在短事务中保存内部占位，再释放数据库连接和行锁调用模型。
结束时验证占位并在同一事务保存评分、练习记录和进度。
正在评分的重复请求返回 409，已评分且答案相同的重试返回原结果。
公开结果中的 `grading` 用于前端恢复后自动刷新结果，内部占位令牌不返回客户端。
评分超过 180 秒会取消并释放占位，失败不推进进度；进程异常退出时占位最多 210 秒后允许重试。
过期旧请求不能覆盖新请求的结果。

删除题库题目采用软删除：题目不再出现在题库、分类、检索、新练习和新面试选题中。
已有面试仍按保存的快照作答，已完成成绩仍进入统计。
删除整个知识库或用户时，相关记录按原有级联关系清理。
