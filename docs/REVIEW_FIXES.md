# 安全与可靠性加固记录

本文件记录认证、RAG、练习评估与大模型配置这几个环节上**发现过的问题、修法与验证方式**。
保留它的目的不是流水账，而是让后来者知道「这些地方曾经出过错，改动时别退回去」。

## 认证与鉴权

| 问题                             | 修法                                                                         |
| -------------------------------- | ---------------------------------------------------------------------------- |
| JWT 使用公开默认密钥             | 读取服务端 `SECRET_KEY`；启动与签发/验证时都拒绝缺失、过短或仍是示例值的密钥 |
| 登录回跳可指向外站（开放重定向） | 排除反斜杠、空白和控制字符，解析 URL 后校验同源；无效路径回落到知识库列表    |
| 错误密码被当成登录过期           | 登录与注册的 401 保留服务端错误信息；只有受保护请求的 401 才清除会话并跳转   |
| 旧请求的 401 误清新令牌          | 清除前校验该 401 属于当前令牌（详见 [auth-session.md](./auth-session.md)）   |

## 数据归属隔离

| 问题                 | 修法                                                                               |
| -------------------- | ---------------------------------------------------------------------------------- |
| 练习可访问他人的题目 | 通过题目所属知识库的 `user_id` 校验；未授权时不调用模型、不写记录                  |
| 向量检索可能跨库召回 | 集合按知识库隔离，检索期再用 `id in [...]` 限定有效切片；禁用/删除的内容不进上下文 |
| 简历删改越权         | 删除与导出均先校验归属                                                             |

## RAG 与检索

| 问题                       | 修法                                                                                   |
| -------------------------- | -------------------------------------------------------------------------------------- |
| 聊天实际不走 RAG           | 前端默认开启检索；后端从当前用户知识库读取文档切片与题目，走 BGE + Milvus + BM25 + RRF |
| 向量库不可用导致对话失败   | 降级为纯关键词检索并标记 `keyword_only`，下一请求自动重试建索引                        |
| 精排失败成为新的故障点     | 精排异常静默退回 RRF 顺序；候选数不足时直接跳过精排                                    |
| 重复导入产生脏数据         | 索引使用 upsert；按内容 SHA-256 差分，仅重新向量化变更分片                             |
| 引用数据格式不一致导致白屏 | 后端统一返回数组（历史数据里的 JSON 字符串在服务端反序列化）；前端再做一次归一化防御   |

## 大模型调用

| 问题                           | 修法                                                                                  |
| ------------------------------ | ------------------------------------------------------------------------------------- |
| 模型配置硬编码在服务端环境变量 | 改为**用户级配置**（`user_llm_configs` 表）；所有调用点统一走 `resolve_llm_config()`  |
| API Key 明文回传前端           | 接口一律只返回脱敏形式 `api_key_masked`；前端提交留空表示沿用已保存的密钥             |
| 无效配置在运行时才报 401       | 保存前校验 URL 结构；提供连通性测试接口，错误信息经 `describe_llm_error` 转成可读提示 |
| 系统代理导致本地模型不可用     | 回环地址自动并入 `NO_PROXY`（系统代理访问 `127.0.0.1` 常返回 502）                    |
| 评分按关键词字符计分（假评分） | 先解析关键词 JSON，再调用模型；严格校验分数与结构，模型失败或结果无效时不保存评分     |

## 占位接口

| 问题                         | 修法                                                                                           |
| ---------------------------- | ---------------------------------------------------------------------------------------------- |
| 启停、统计和删除返回假的成功 | 文档启停写数据库；详情返回有序分块；引用统计读取已持久化消息；简历删除校验归属并清理文件与记录 |

## 验证方式

```bash
cd background
python -m pytest tests -q          # 142 个用例
python -m pip check

cd ..
pnpm test                          # 5 个前端回归脚本
pnpm tsc --noEmit && pnpm run lint
```

后端回归使用独立测试库；Milvus、向量化模型及外部评分 API 均以测试替身注入。
聊天测试会真实经过 prompt、SSE 与消息落库。外部模型测试使用真实 OpenAI 客户端配合
模拟 HTTP 响应，覆盖合法与异常输出。

> **这些检查不等于真实 Milvus 与生产模型的端到端验收**，也不代表其他部署问题已全部解决。
